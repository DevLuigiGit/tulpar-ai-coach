# MCP-демо: инструменты тренера через tulpar-mcp

`tulpar-mcp` — stdio-сервер MCP (`python -m tulpar_ai.mcp_server`). Он даёт AI-ассистенту тренера (Claude Desktop,
Claude Code) пять инструментов сервиса. Сервер — тонкий клиент HTTP API: ходит в `SERVICE_URL` с `INTERNAL_SECRET`
от имени тренера, поэтому права и маскирование данных клиентов проверяет сам сервис. Пример конфигурации лежит в
`mcp/claude_desktop_config.example.json`.

## Как проверяли

1. Claude Code в headless-режиме с временным конфигом только для этого сервера:

   ```bash
   claude -p --mcp-config <временный.json> --strict-mcp-config --allowedTools "mcp__tulpar-mcp" \
     "Я тренер. Покажи моих клиентов и предложи Айдару облегчить план из-за боли в колене."
   ```

   Claude Code запустил сервер: `tulpar-mcp` в статусе `connected`, найдено 5 инструментов (`list_clients`,
   `get_client_context`, `search_exercises`, `propose_program_change`, `list_pending_proposals`). До вызовов
   инструментов прогон не дошёл: CLI на этой машине не прошёл авторизацию (истекла OAuth-сессия). Временный
   конфиг удалён, глобальные настройки Claude не менялись.

2. Поэтому транскрипт ниже снят официальным MCP-клиентом на Python (`tools/mcp_demo.py`). Он запускает тот же
   сервер по stdio, как это делает MCP-хост, получает список инструментов и вызывает их в порядке, который сервер
   советует в своих `instructions`:

   ```bash
   python -m tulpar_ai                                  # сервис
   python tools/mcp_demo.py --base http://localhost:8089
   ```

## Что показал прогон

- **Модель ошиблась в идентификаторе упражнения.** Первый прогон того же запроса (черновик `2abd60fb`, 6,0 с)
  заменил «Приседания со штангой» на «Бёрпи с отжиманием». В тексте операции модель пишет, что ставит
  «изоляцию квадрицепса в тренажёре», а в обосновании называет «сгибания ног сидя в тренажёре». Но `exercise_id`
  в операции принадлежит «Бёрпи с отжиманием» из группы «кардио». Выбранное моделью упражнение и записанный id
  не совпадают, и тренер увидел бы «Бёрпи» рядом с обоснованием про другое упражнение. Валидатор тогда это
  пропустил: группу мышц у замены он не сверял, а противопоказаний у «Бёрпи» в каталоге нет.
- **Исправление: валидатор сверяет группу мышц при замене.** Правило «замена из той же группы мышц» уже было
  в Skill, теперь его проверяет `validate_plan.py`. Если силовое упражнение меняют на кардио или растяжку (или
  наоборот), это ошибка `E_MUSCLE_GROUP`: черновик уходит на новую попытку с текстом ошибки. Если замена
  остаётся силовой, но из другой группы, это предупреждение `W_MUSCLE_GROUP`, и решает тренер. Пресс и кор
  считаются одной группой.
- **Проверка на сохранённых черновиках.** Новый валидатор прогнан на 6 черновиках из прогонов 25.09.2026.
  Черновик `2abd60fb` теперь получает `E_MUSCLE_GROUP`: «Бёрпи с отжиманием» (кардио) вместо «Приседания со
  штангой» (ноги). Черновик `59e67d98` из транскрипта выше получает `W_MUSCLE_GROUP` за «Гиперэкстензия с весом»
  (спина) вместо «Румынская тяга» (ноги). Это тот же наклон с разгибанием в тазобедренном суставе, поэтому
  только предупреждение. У остальных 4 черновиков набор замечаний не изменился.
- **Golden-набор.** В `evals/golden/program.jsonl` добавлен случай `wrong_group` с той же заменой приседа на
  бёрпи. В двух старых случаях (`back_contra`, `home_machine`) генератор теперь берёт замену из той же группы,
  чтобы каждый случай проверял одну ошибку. Итог `evals/run.py program`: 13 случаев, exact match 100%.
- **Противопоказания в каталоге заполнены у 43 из 196 упражнений.** Это отдельное ограничение: поэтому
  «Фронтальные приседания», «Приседания в смите» и «Выпады со штангой» проходят фильтр
  `avoid_problems_with="колено"` в `search_exercises`. Заполненные противопоказания поймали бы именно случай с
  бёрпи, но не следующую ошибку в id, если ошибочное упражнение безопасно для колена. Такую ошибку ловит только
  проверка группы.
- Черновик не применяется без тренера. Так и задумано: решение по плану принимает человек.
