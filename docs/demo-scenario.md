# Сценарий защиты: от сообщения клиента до изменённого плана

Один сквозной прогон против запущенного сервиса. Клиент задаёт вопрос по базе знаний, пишет, что съел, и просит
добавить кардио. Агент собирает черновик изменения программы, тренер видит его в очереди и принимает. План
клиента действительно меняется. В конце скрипт находит в LangSmith трейсы именно этого прогона.

```bash
python -m tulpar_ai                                    # сервис на :8089 (порт меняется через PORT)
python tools/demo_scenario.py --base http://localhost:8089
```

Если у черновика остались ошибки валидатора (`severity=error`), скрипт его не принимает. Тренер один раз
возвращает черновик на доработку, в комментарии перечислены ошибки. Если и новый черновик с ошибками, тренер его
отклоняет, скрипт завершается с кодом 1, а план клиента не меняется.

## Что видно в прогоне

- Каждый ход чата даёт ровно один трейс `coach_turn`. Черновик, который запускает ход «Хочу добавить кардио»,
  вложен в тот же трейс по цепочке `program_request → program_change → draft`. У этого хода 3 LLM-вызова:
  маршрутизатор и две попытки черновика. В первой модель поставила кардио 1 подход × 1 повторение, валидатор
  вернул `E_VOLUME` (допустимо 3–25 повторений), вторая попытка прошла без ошибок.
- Решение тренера — отдельный трейс `program_change`. Это возобновление графа после паузы, без LLM.
- Черновик собран за 20,2 с (шаги 4 → 6), весь сценарий занял 33,7 с.
- «Чай» записан как «Чай чёрный без сахара»: 150 г ≈ 2 ккал.
- Ссылки на трейсы открываются только участникам LangSmith-организации проекта.

Прогоны 1–3 сделаны до двух исправлений, прогон 4 — после них:

- **Черновик с ошибкой больше не применяется.** Во 2-м прогоне валидатор трижды вернул черновик из-за
  `E_VOLUME`: для кардио модель ставила в поле повторов 1 или 40 (похоже на длительность). Третья попытка ушла
  тренеру с ошибкой, и старая версия скрипта всё равно нажала «принять». В план демо-клиента попало кардио на 40
  повторений. Теперь скрипт такой черновик возвращает на доработку, а если ошибка осталась — отклоняет.
- **«Чай» и «кофе» ищутся без добавок.** Раньше поиск по справочнику выбирал «Чай с мёдом» (26 ккал/100 г)
  вместо «Чай чёрный без сахара» (1 ккал/100 г), а «кофе» — «Раф-кофе» (92 ккал/100 г). Причина была в том, что
  слово «без» считалось стоп-словом: «Чай чёрный без сахара» проигрывал более короткому названию. Теперь «без X»
  в названии учитывается, только если клиент сам написал «без X», а каждая добавка «с X», о которой клиент не
  писал, немного снижает оценку. На 1629 запросах (все 1305 названий справочника, их первые слова и 20 частых
  блюд) лучший результат изменился у 10. Восемь из них — исправления того же рода: «чай», «кофе», «чай без
  сахара», полные названия «… без сахара», которые раньше находили вариант «с сахаром». Ещё два — запросы из
  одного слова без однозначного ответа: «Гусь» и «Куриное». Порог совпадения 0,34 ни один запрос не перешёл ни в
  одну сторону. Точных попаданий по полному названию стало 1278 из 1305 (было 1275).
