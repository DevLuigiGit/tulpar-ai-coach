# Tulpar AI Coach

AI-коуч для фитнес-платформы [Tulpar](https://tulpar-664.pages.dev): клиент присылает фото еды, голосовое или вопрос, а агент считает калории по каталогу продуктов, отвечает со ссылками на источники и готовит черновики изменений программы тренировок. **Менять программу может только тренер** — одним нажатием в вебе или в Telegram.

Финальный проект курса nFactorial по LLM-инженерии.

**Для кого.** Тренер фитнес-клуба с 15–40 клиентами в мессенджерах и его клиенты.
**Какая боль.** Тренер тратит часы на однотипные ответы («что съесть», «замени упражнение»), клиенты бросают дневник питания через неделю, потому что вбивать еду руками долго, а отток замечают слишком поздно. Сейчас это решают перепиской в WhatsApp, таблицами и отдельными счётчиками калорий, не связанными с тренером.

## Что умеет

| Сценарий | Как работает |
|---|---|
| Фото еды → калории | vision-модель узнаёт блюда, граммы и КБЖУ берутся из каталога Tulpar на 1305 продуктов, клиент правит граммы и записывает в дневник |
| Голосовое «съел 200 г плова и чай» | распознавание речи → извлечение продуктов → та же карточка |
| Вопрос о технике, питании, нормах | RAG по 196 карточкам упражнений, правилам питания и рекомендациям ВОЗ 2020 с цитатами и страницами |
| Боль, травма, лекарства, беременность | ответа от модели нет: сообщение уходит тренеру, клиенту — безопасный текст |
| «Замените присед, колено» | черновик правок по Skill → проверка валидатором → очередь тренера → «Принять / Поправить / Отклонить» |
| Claude Desktop тренера | MCP-сервер `tulpar-mcp`: клиенты, контекст, поиск упражнений, черновик изменений, очередь |

## Запуск

Нужны Python 3.12 и Node 22.

```bash
make install
cp .env.example .env
make run
```

Откройте http://localhost:8089 и войдите демо-клиентом или демо-тренером. Без ключей сервис тоже стартует: маршрутизация работает на правилах, поиск — на локальных эмбеддингах, а вопросы без модели уходят тренеру. Для полной работы впишите ключи в `.env` и проверьте их:

```bash
make keys
```

| Команда | Что делает |
|---|---|
| `make test` | тесты без сети и ключей: пауза тренера переживает перезапуск, валидатор, сквозной сценарий API |
| `make evals` | евалы: валидатор, маршрутизатор, RAG |
| `make mcp` | MCP-сервер для Claude Desktop (сервис должен быть запущен) |
| `make export` | заново выгрузить демо-данные и корпус из локального репозитория Tulpar (только чтение) |

**Режимы.** `TULPAR_MODE=demo` (по умолчанию) — демо-тренер и два демо-клиента, их программы и дневник хранятся в самом сервисе. `TULPAR_MODE=tulpar` — работа с локальным стендом Tulpar через его API; адрес прода запрещён проверкой при старте.

**Telegram.** Впишите токен бота в `TELEGRAM_BOT_TOKEN`, а свой числовой ID в `TRAINER_TELEGRAM_IDS` — тогда бот считает вас тренером. Бот опрашивается одним процессом: запускайте его либо локально, либо на Railway.

**Claude Desktop.** Скопируйте блок из `mcp/claude_desktop_config.example.json` в конфиг Claude Desktop, поправьте пути и перезапустите приложение.

## Демо за 3 минуты

1. Клиент: «Съел 200 г плова и чай» → карточка с калориями → «Записать».
2. Клиент: фото тарелки → распознанные блюда из каталога.
3. Клиент: «Сколько минут активности в неделю рекомендует ВОЗ?» → ответ с цитатой и страницей.
4. Клиент: «Колено болит при приседе» → эскалация тренеру, клиенту — безопасный ответ.
5. Клиент: «Тренер знает про колено, замените присед на что-то щадящее» → черновик в очереди тренера.
6. Тренер: видит «было → станет» и проверку Skill → «Принять» → программа клиента обновилась.
7. LangSmith: трейс этого сценария целиком.

## Деплой на Railway

Отдельный проект Railway, не проект Tulpar. Сервис из этого репозитория собирается по `Dockerfile` (веб и API в одном контейнере), healthcheck `/health` задан в `railway.json`. Нужен volume, смонтированный в `/data` (`AI_DATA_DIR=/data`), и переменные из `.env.example` с длинными случайными `JWT_SECRET` и `INTERNAL_SECRET`. На Railway работает демо-режим.

## Структура

```
tools/            выгрузка из Tulpar, проверка ключей
```
